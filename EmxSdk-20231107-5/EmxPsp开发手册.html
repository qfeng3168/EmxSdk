介绍

  PSP(Product-Support-Package)由Emx开发人员进行制作，为应用开发提供底层配置支持，其包含的内容有

├── configs
├── param
└── psp.json

  其中的configs和param是EmxSdk中一部分模块的配置和参数，psp.json是psp的配置文件。Emx开发人员将psp制作完毕后交付给应用开发人员进行应用开发
  当产品执行构建脚本product.json的时候，会默认的将configs和param目录拷贝到firmware目录，并处理psp.json中的配置信息

psp的修改

  按照如下步骤对psp进行修改后交付应用开发人员进行应用开发

修改psp.json

  psp.json对产品的底层信息进行描述，包括所使用的编译链，EmxMedia以及分区等信息

{
  "Cross": "x86_64",
  "CrossPath": "",
  "EmxMediaVersion": "EmxMedia-Debug",
  "EmxMediaProfile": "chipXDefault",
  "partition": {
    "flashImgSize": "16M",
    "partitionTable": [
      {"name": "boot", "file": "boot.bin", "size": "384K"},
      {"name": "env", "size": "128K"},
      {"name": "kernel", "file": "kernel.bin", "size": "2432K"},
      {"name": "rootfs", "file": "rootfs.bin", "size": "1M"},
      {"name": "firmware", "file": "firmware.bin", "size": "9408K"},
      {"name": "spare", "file": "spare.bin", "size": "2560K"},
      {"name": "data", "size": "448K"}
    ]
  },
  "EmxResToProduct": [
    {
      "src": "imgs/boot/boot-cv1821-gun-pub.bin",
      "dst": "imgs/boot.bin"
    },
    {
      "src": "imgs/kernel/kernel-cv1821-default.bin",
      "dst": "imgs/kernel.bin"
    },
    {
      "src": "imgs/rootfs/rootfs-cv1821-default.bin",
      "dst": "imgs/rootfs.bin"
    },
    {
      "src": "imgs/scripts/mkImg-16MB-spare-default.py",
      "dst": "imgs/mkImg.py"
    }
  ]
}
  • Cross：定义了产品使用的交叉编译链
  • CrossPath：定义了产品使用的交叉编译链所在的绝对路径，一般不需要填写，当编译过程无法找到编译链时填写
  • EmxMediaVersion：产品需要使用的EmxMedia的版本
  • EmxMediaProfile：产品需要使用的EmxMedia的profile
  • partition：flash的分区信息，flashImgSize代表打包整个flash的时候，最终生成flash.bin文件的大小，partitionTable分区表，其中name字段是分区名，"file"字段是对应的bin文件名，当这个字段不存在时代表不需要烧入镜像文件，size分区大小
  • EmxResToProduct：应用更新产品的时候将资源文件中需要使用的文件映射到产品目录，例子中将EmxRes中产品需要用到的imgs文件和脚本映射到了产品imgs目录

修改boot配置

  configs下的boot配置文件夹对应于boot模块，是应用层读写uboot环境变量所需要的配置文件.
  default文件是uboot的默认环境变量，当uboot配置完成后烧录到设备中启动，然后输入pri指令即可获取到uboot的默认环境变量，将其内容拷贝至default文件中即可。
  env.cfg文件是uboot环境变量的分区信息，需要结合uboot中的定义进行修改，uboot的env分区为了进行备份，需要划分为至少两个flash块，有两种划分方式，一种是将env分区映射到一个mtd设备上，然后定义两个相互备份的flash块的大小和偏移，例如下面的方式，env分区挂载到/dev/mtd1设备上，划分为两个64KB的区域，推荐这种方式

# MTD device name	Device offset	Env. size	Flash sector size	Number of sectors
/dev/mtd1		0x0000		0x10000		0x10000
/dev/mtd1		0x10000	  0x10000		0x10000

另一种方式是将env的两个分区挂载到两个设备上，例如下面的方式，将两个64KB的分区挂载到两个不同的设备上

# MTD device name	Device offset	Env. size	Flash sector size	Number of sectors
/dev/mtd1		0x0000		0x10000		0x10000
/dev/mtd2		0x0000	  0x10000		0x10000

修改media配置

  默认的psp中只包含了EmxSdk中的配置文件，psp开发人员需要确认所需的EmxMedia版本和profile，并将EmxMedia配置文件整合进来。首先拷贝EmxMedia/某个/profile中的configs下的所有内容到psp/confgis/media/scene/default目录下，然后结合经验对psp/confgis/media和psp/param/media进行修改

修改bsp.json

  bsp模块提供应用程序操作设备外围接口功能。bsp模块依赖的配置文件是bsp.json，这个配置文件通常由Emx开发人员预先根据硬件板配置好，配置内容如下：

{
  "led": {
    "class": "BspLed",
    "defaultChnIdx": 0,
    "channels": [
      {
        "dir": 1,
        "active": true,
        "default": true,
        "num": 402
      }
    ]
  },
  "keyReset": {
    "class": "BspKeyReset",
    "defaultChnIdx": 0,
    "channels": [
      {
        "dir": 0,
        "active": false,
        "default": false,
        "num": 510
      }
    ]
  },
  ...
}

其中类似led和keyReset为预定义的外围接口类型，外围接口的定义大多数情况下是针对GPIO的操作，这类接口具有相类似的描述结构。

channels

channels描述这个接口需要的gpio通道，有可能一个外围接口需要多个gpio来操作，例如双线控制的IRCUT。

    "channels": [
      {
        "dir": 1,
        "active": true,
        "default": true,
        "num": 402
      }
    ]
Key Type Description
dir int gpio的输入输出方向，0：输入，1：输出
active bool 有效的极性，true：高有效，false：低有效
default bool 默认的有效状态，true：默认有效，false：默认无效
num int 这个gpio在/sys/class/gpio下的序号

defaultChnIdx

    "defaultChnIdx": 0,

这个字段指示，当外部操作这个接口，但不指明操作接口具体的那个gpio通道时，内部默认选择的通道号，这个通道号就是gpio的channels数组的索引下标

class

    "class": "BspKeyReset"

每个外围接口可能在设备内部有不同的实现方式，class字段指明这个接口选择哪种实现方式，不同的实现方式，后面具体的描述字段可能会不同

      -1

Key Type Description
invMs int led闪烁间隔
allChannels obj array led所使用的gpio数组
